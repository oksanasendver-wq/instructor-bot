# Запуск INSTRUCTOR

Проект работает самостоятельно, без Docker. Для локальной проверки нужны Node.js 22.12+ и Python 3.13.

## Локальный запуск с данными школы

После настройки `backend/.env`, применения миграций и установки зависимостей запустите `./start-local.ps1`. Он запускает настоящий API и оба интерфейса, не создаёт тестовых учеников и не включает обход Telegram. Вход администратора — из настроек backend. Миниап требует авторизации через Telegram; для работы на телефоне используйте HTTPS-размещение, описанное ниже.

## Изолированный тестовый стенд

В PowerShell из `E:\PROJECTS\INSTRUCTOR`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
npm ci
.\start-local.ps1 -TestPreview
```

Откройте:

- Миниап: http://127.0.0.1:5173
- Админка: http://127.0.0.1:5174
- Вход администратора: `local-admin` / `instructor-local`.

Скрипт держит три процесса, пишет логи в `.local` и останавливает их по Ctrl+C. Если порт занят, завершите предыдущий локальный запуск. Запуск не читает рабочие реквизиты из `.env`: сервер подменяет их изолированными значениями, создаёт новую SQLite-базу в `backend/.local` и использует подписанные тестовые данные Telegram. Каждый перезапуск сервера создаёт новый набор демонстрационных данных. Этот режим предназначен только для своего компьютера; его нельзя публиковать через туннель.

Время демонстрационной школы начинается с 12:00. У Марии есть занятие 12:00–13:00. Нажмите «Пришёл», при необходимости подтвердите получение наличных. Чтобы сразу проверить завершение, в другом PowerShell выполните:

```powershell
Invoke-RestMethod -Method Post 'http://127.0.0.1:8010/__preview/clock?minutes=61'
```

Обновите миниап, завершите занятие, выберите упражнение, оценки навыков, самостоятельность и общую оценку. После сохранения откройте Марию в админке: история и скор обновлены. У Ивана намеренно оставлен просроченный отчёт для проверки повторного доступа администратора.

## Настоящий backend и Telegram

1. Создайте отдельную PostgreSQL-базу. Скопируйте `.env.example` в `backend/.env`, заполните реквизиты, случайный `SECRET_KEY`, пароль администратора, токен бота и секрет webhook. Не заменяйте уже заполненный файл без проверки.
2. Из `backend` выполните:

```powershell
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m scripts.seed_data
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

3. Для интерфейсов запускайте `npm run dev --workspace instructor-miniapp` и `npm run dev --workspace instructor-admin` из корня в отдельных терминалах. По умолчанию `/api` и `/admin` проксируются на `127.0.0.1:8000`. Локальный вход без Telegram в этом режиме отключён.
4. Для Telegram разместите backend и miniapp на HTTPS. Задайте фактические origins в `FRONTEND_MINI_APP_URL` и `FRONTEND_ADMIN_URL`. В обоих фронтендах `VITE_API_URL` должен указывать на HTTPS backend **без** `/api` или `/admin`; требуется новая сборка после изменения переменной.
5. В BotFather задайте URL miniapp для кнопки меню. Установите webhook бота на `https://<backend>/api/telegram/webhook`, передав `secret_token`, совпадающий с `TELEGRAM_WEBHOOK_SECRET`. Добавьте инструктора с его телефоном в админке. Первый вход через кнопку бота попросит передать собственный контакт.

Пустые AI-ключи не мешают работе школы. Для черновиков заключений задайте `AI_PROVIDER=groq` и `GROQ_API_KEY` либо `AI_PROVIDER=nvidia` и `NVIDIA_API_KEY`. Администратор проверяет и утверждает текст; AI не меняет баллы.

## Проверки

```powershell
npm run build
npm run test:ui
cd backend
..\.venv\Scripts\python.exe -m playwright install chromium
..\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют собственные базы и подмену доставки Telegram. Браузерные тесты открывают собранные интерфейсы и обращаются к настоящему API на изолированной базе: проверяют вход, одно занятие без ложной динамики, открытие закрытого отчёта, кнопки профиля, админскую карточку и сохранение оценки навыка 0. Сначала завершите сборку, затем запускайте тесты. Проверка `npm run test:ui` требует Node.js 22.18+ и проверяет периоды, часовой пояс, исправления одного занятия и смену версии методики.

## Render и Vercel

Backend: рабочая папка `backend`, build `pip install -r requirements.txt`, перед запуском `python -m alembic upgrade head` и `python -m scripts.seed_data`, start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`. Миграции выполняйте одним процессом. Перед обновлением существующей базы сделайте резервную копию.

Два проекта Vercel используют корень репозитория, поскольку код `shared` нужен обоим. Install: `npm ci`. Для miniapp build `npm run build:miniapp`, output `frontend-miniapp/dist`; для админки build `npm run build:admin`, output `frontend-admin/dist`. Роутинг использует hash, специальный rewrite не нужен. `VITE_LOCAL_PREVIEW` на публикации не задавайте. Сервер запускайте через `app.main:app`, никогда через `scripts/local_preview.py`.

На существующей базе seed сохраняет уже заполненные справочники. Сверьте их с `NEW_TZ.md` через админку: переименование не меняет исторические названия упражнений. Миграция 005 трактует прежние временные отметки как UTC.
