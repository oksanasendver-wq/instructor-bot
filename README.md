# INSTRUCTOR

Telegram Mini App инструктора и административный интерфейс школы. Основное ТЗ — [NEW_TZ.md](NEW_TZ.md). Инструкция установки, демонстрационного режима и подключения Telegram — [QUICKSTART.md](QUICKSTART.md).

Инструктор видит назначенные занятия, отмечает приход и получение оплаты, завершает практику, выбирает упражнения и кратко оценивает навыки. Отчёт, флаги внимания и баллы сохраняются одной транзакцией. Черновик остаётся в текущей вкладке при проблемах со связью; успешное сохранение подтверждает сервер.

Миниап показывает только сохранённые оценки и заключения школы. Без оценок города городской балл отсутствует; одного занятия недостаточно для динамики. Периоды графика: 3 дня, неделя, месяц и 3 месяца. Исправление отчёта не считается новым занятием, а результаты разных версий методики не сравниваются как прогресс. Занятия открываются для чтения независимо от срока редактирования при наличии доступа к ученику. В профиле инструктора работают статистика, серверное время школы и сведения о приложении. Навыки оцениваются по шкале 0–4 в обоих интерфейсах, общая оценка занятия — 1–5; форма не подставляет наблюдения за инструктора.

Администратор создаёт и изменяет учеников, инструкторов и расписание, видит прогресс, историю, часы практики и вмешательства. Клиенты с учебной историей архивируются, архив доступен для просмотра и восстановления. Инструктора можно деактивировать и активировать снова. Исправления отчётов, повторный доступ и заключения имеют журнал изменений. Справочники редактируются с сохранением версий и исторических названий упражнений.

## Расчёт

- Навык: последние три **реальные** оценки 0–4, нормализованные веса свежести 0,5/0,3/0,2. Пропущенный навык не превращается в ноль.
- Контекст: взвешенное среднее оценённых навыков. Основные веса площадки 15/15/15/15/20/20, города 10/20/15/15/10/15/5/10. Админские веса нормализуются при расчёте.
- Самостоятельность: преобладающий уровень последних трёх уроков, при равенстве — самый свежий. Ограничения A0/A1/A2/A3: 55/70/85/100.
- Безопасность последних трёх уроков контекста: физическое вмешательство ограничивает 70, критическое событие 60, повторное физическое 50. Ограничения снимаются после трёх безопасных уроков.
- Достоверность: минимум три урока и не менее двух оценок у 80% основных навыков. До этого показывается предварительный результат.
- Общая готовность: только при достоверности обоих контекстов, округлённые 40% площадки + 60% города. Критическое событие за последние десять занятий ограничивает общий балл 70.
- 100 баллов требуют минимум пяти занятий каждого контекста, трёх последних оценок 4 у каждого основного навыка, A3 на последних трёх уроках обоих контекстов, отсутствия физических/критических вмешательств в последних десяти уроках и активных флагов. Иначе верхняя граница 99.

Каждый пересчёт добавляет снимки формулы, входных данных и ограничений. AI-черновики отделены от детерминированного расчёта и утверждённых версионных заключений.

## Доступ и время

Клиент доступен назначенному инструктору с создания записи до окончания занятия +60 минут. После отметки «Пришёл» ученик остаётся в списке и карточке этого инструктора; неявка постоянного доступа не даёт. Приход отмечается от начала −30 минут до окончания, завершение и неявка — после окончания. Незакрытое занятие после истечения срока требует администратора. Собственный отчёт редактируется 30 минут; критические вмешательства нельзя убрать самостоятельно. Администратор может открыть конкретную запись повторно на 30 минут с причиной.

Расписание использует часовой пояс школы (`TIMEZONE`, по умолчанию `Asia/Almaty`); события и сроки разрешений хранятся в UTC. Проверка просроченных состояний выполняется при запросах расписания, отдельный планировщик не требуется.

## Структура

`backend` — FastAPI, SQLAlchemy, Alembic и PostgreSQL; `frontend-miniapp` и `frontend-admin` — React/TypeScript/Vite; `shared` — общие типы, компоненты и оформление. Корневой npm workspace и lockfile устанавливают зависимости обоих интерфейсов. Docker не используется.

Проверки запускаются после сборки: `npm run build`, `npm run test:ui`, затем `python -m pytest -q` из `backend`. Они покрывают расчёты, доступ, версии методики, отсутствие ложного прогресса, вход через Telegram, чтение отчётов в обоих интерфейсах и явное сохранение наблюдений. Браузерные тесты используют собранные приложения с настоящим API на изолированной SQLite-базе. SQLite-тесты не проверяют блокировки PostgreSQL при конкурентных запросах. Реальное открытие внутри мобильного Telegram, применение миграций на PostgreSQL и запросы AI с ключами требуют проверки на отдельном стенде перед внедрением. Ограничитель частоты входа/AI действует на процесс; при нескольких backend workers нужен общий лимит на прокси.
